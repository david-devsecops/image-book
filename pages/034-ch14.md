## 증상부터 분리합니다

원하는 결과가 나오지 않았을 때 ‘다시 잘 만들어 줘’라고 요청하면 바뀌는 범위가 너무 넓습니다. 먼저 무엇이 문제인지 분류하세요. 빠진 물체, 잘못된 수량, 어긋난 위치, 글자 오류, 원본 변형, 다운로드 실패는 서로 다른 문제입니다. 파일 저장 오류를 프롬프트로 고칠 수는 없습니다.

| 증상 | 먼저 확인할 것 | 다음 시도 |
| --- | --- | --- |
| 물체가 빠짐 | 여러 요구에 묻혔는지 | 핵심 대상을 짧게 다시 명시 |
| 수량이 다름 | 소품과 주인공의 관계 | 수량을 줄이고 배치를 나눔 |
| 글자 오탈자 | 실제 결과를 확대했는지 | 짧은 문구로 수정하거나 후편집 |
| 원본까지 달라짐 | 유지 조건과 입력 파일 | 원본에서 다시 최소 편집 |
| 비율이 다름 | 실제 픽셀 크기와 지원 설정 | 설정을 확인하고 최종 크기 조정 |
| 결과 파일이 없음 | 생성 완료·오류 안내 | 상태 확인 후 다운로드 재시도 |

문제가 두 가지라면 사용을 막는 문제부터 고칩니다. 메뉴 이름이 틀렸고 배경이 약간 어두우면 메뉴 이름이 먼저입니다. 글자가 들어갈 여백 자체가 없다면 글자 수정 전에 구도를 고쳐야 합니다. 순서에는 의존 관계가 있습니다.

## 같은 수정이 반복해서 실패할 때

같은 요청을 두 번 바꾸어도 나아지지 않으면 더 긴 문장으로 밀어붙이기보다 원본과 목표를 다시 봅니다. 한 번에 요구한 변화가 너무 큰지, 도구가 해당 편집을 지원하는지, 문제 부분을 일반 편집 프로그램으로 처리할 수 있는지 확인하세요.

글자를 정확한 폰트로 넣거나 로고의 위치를 일정하게 맞추는 작업은 일반 편집 도구가 더 예측 가능할 수 있습니다. 이미지 생성이 모든 단계를 담당할 필요는 없습니다. AI로 배경을 만들고 글자는 나중에 배치하는 선택도 정상적인 제작 과정입니다.

독자 과제: 마음에 들지 않는 결과를 하나 고르고 ‘증상, 근거, 다음 한 가지 수정’의 세 줄을 씁니다. 실제로 보이지 않는 결함을 추측해 적지 마세요. 관찰한 사실과 원인에 대한 추정은 다른 문장으로 남깁니다.
