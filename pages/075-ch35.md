## 하루에 한 가지 판단을 익힙니다

이 일정은 학습량을 나누는 제안입니다. 하루 분량을 이틀에 나누어도 됩니다. 이미지 생성 횟수보다 요청과 결과를 비교한 기록을 남기는 것이 중요합니다. 각 날의 수록 사례를 먼저 읽고 직접 실행할 연습 하나를 고르세요. 모든 예시를 하루에 재생성할 필요는 없습니다.

| 날 | 살펴볼 실제 사례와 할 일 | 남길 결과 |
| --- | --- | --- |
| 1일 | Ch04 잔 생성, Ch13 한국어·영어 비교 | 첫 프롬프트와 조건 비교표 |
| 2일 | Ch08 확산광·직사광, Ch09 종이·금속 | 빛과 표면 관찰 기록 |
| 3일 | Ch16 파랑·녹색 배경, Ch17 지우개 제거 | 변경 범위와 보존 항목 |
| 4일 | Ch19 창가 잔, Ch21 상자 색 변경 | 형태·배치 비교표 |
| 5일 | Ch22 투명 배경, Ch23 행사 배경, Ch24 두 장면 | 투명도와 시리즈 일관성 판정 |
| 6일 | Ch26~30 카페 프로젝트 설계·제작·검수 | 요청서와 메뉴 시안, 오류 기록 |
| 7일 | 문제 풀이와 작업 정리 | 답안, 재사용 양식, 다음 목표 |

실행 환경이 없는 날에는 프롬프트의 모순을 찾거나 기존 결과를 관찰하는 연습을 할 수 있습니다. 다만 이 활동을 실제 생성 실습으로 기록하지 않습니다. 어떤 학습을 했는지 정확하게 남기는 편이 다음 계획에 도움이 됩니다.

## 다음에는 무엇을 배울까요

글자 배치가 어렵다면 기본 편집 도구의 텍스트, 정렬, 여백 기능을 배워 보세요. 제품 보존이 어렵다면 선택 영역과 비파괴 편집을 익히는 것이 도움이 됩니다. 파일 관리가 자주 꼬인다면 생성 횟수를 늘리기 전에 이름과 백업 규칙부터 정리합니다.

API는 여러 작업을 프로그램에서 호출하는 통로입니다. 이미지 생성 원리를 배우기 위해 반드시 필요한 단계는 아닙니다. 반복 작업의 양이 많고 직접 비용과 오류를 관리할 필요가 생겼을 때 검토하세요. 이 판에는 실제 API 호출을 검증한 코드 부록을 포함하지 않았습니다.

## 자신의 작업을 설명해 봅니다

마지막으로 완성한 이미지 한 장을 고르고 네 질문에 답해 보세요. 왜 만들었는가, 무엇을 입력했는가, 무엇을 고쳤는가, 어떤 근거로 끝냈는가입니다. 이 네 가지를 설명할 수 있으면 새로운 모델이나 도구를 만나도 다시 적용할 기반이 생긴 것입니다.

앞으로 도구 이름과 메뉴는 바뀔 수 있습니다. 그때도 공식 안내에서 기능을 확인하고, 작은 입력으로 시험하고, 실제 결과를 검사하는 순서는 유지할 수 있습니다. 특정 문장을 외우는 공부에서 자신의 작업을 판단하는 공부로 옮겨 가세요.
