## 폴더 구조를 유지합니다

책 소개는 README.md, 목차는 TOC.md, 본문은 pages, 이미지는 assets에 들어 있습니다. WikiDocs의 GitHub 연동 방식은 목차의 링크와 들여쓰기로 페이지 계층을 구성합니다. 원하는 순서를 유지하기 위해 제목에 번호를 붙였습니다. [GitHub 연동 안내](https://wikidocs.net/321336).

TOC의 001, 002 같은 숫자는 웹 페이지의 정렬 순번이며 종이책의 인쇄 쪽수가 아닙니다. Part는 내용 묶음이고 Chapter는 01~35의 연속된 학습 장 번호입니다. 실제 전자책의 쪽수는 글꼴과 이미지 배치, 변환 결과에 따라 달라지므로 본문에 임의의 인쇄 쪽수를 적지 않았습니다.

각 본문 파일은 페이지 제목을 중복해서 넣지 않고 2단계 헤딩부터 사용합니다. 이미지 앞뒤에는 빈 줄이 있으며 파일 경로는 `../assets/파일명.png` 형식입니다. 이미지 파일도 함께 올려야 링크가 연결됩니다. [전자책 작성 주의사항](https://wikidocs.net/198723).

## 옮기는 순서

1. 로컬에서 책 소개, 목차, 본문과 이미지를 확인합니다.
2. 공개할 범위와 저자 표시를 확정합니다.
3. 지정 저장소에 반영할 파일만 검토합니다.
4. WikiDocs에서 GitHub 연결 또는 수동 페이지 작성을 진행합니다.
5. 동기화 후 첫 페이지, 목차 계층, 표와 이미지를 확인합니다.
6. 전자책을 만들 경우 변환한 파일에서 한글과 페이지 나눔을 확인합니다.

수동으로 옮길 때는 TOC의 제목을 페이지 제목으로 사용하고 각 Markdown 본문을 붙여 넣습니다. 상대 이미지 경로는 업로드한 WikiDocs 이미지 주소로 바꿔야 합니다. GitHub 연동을 사용할 때의 자동 이미지 경로 변환과 수동 입력을 혼동하지 마세요.

GitHub와 연결된 책은 push가 동기화를 일으킬 수 있습니다. 비공개 원본이나 내부 검수 자료를 출판 폴더에 함께 넣지 않습니다. 이 책의 제공 파일을 준비한 것과 실제 공개 게시를 완료한 것은 다른 상태입니다.
